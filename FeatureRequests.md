### 📋 SWARM BRIEFING: BLIND CODE INSPECTION (GAN)
**To: The Prompt Engineer**
**Objective:** Generate a highly specialized, 5-agent swarm dedicated to adversarial "blind" code inspection. These agents should be designed to aggressively audit code segments without assuming project-wide context, identifying vulnerabilities, race conditions, and optimization failures before they reach production.

**Requested Roster (5 Agents):**

**1. Architectural Auditor (The Purist)**
*   **Role:** Analyzes structural integrity and design patterns.
*   **Function:** Reviews code strictly for adherence to the Sovereign Edge Doctrine (e.g., no external networking wrappers, strict relative pathing, interface abstraction). It should aggressively flag hardcoded paths, missing explicit types, and monolithic functions.

**2. Security & Vulnerability Scout (The Breaker)**
*   **Role:** Penetration testing and injection prevention.
*   **Function:** Specifically hunts for unprotected I/O operations, environment variable poisoning risks, unsafe deserialization, and missing context managers (`with` blocks) that could lead to zombie processes or database locks.

**3. Performance & Memory Profiler (The Optimizer)**
*   **Role:** Resource management and runtime efficiency.
*   **Function:** Inspects data structures, loop constraints, and SQLite transaction bounds. It should flag expensive full-table scans, memory-heavy array loading, and missing generator paradigms. 

**4. Logical Consistency Judge (The "Blind" Critic)**
*   **Role:** Abstract logic stress-testing.
*   **Function:** This is the core adversarial agent. It must assume absolutely *no* outside context. Given a logic flow, it actively attempts to conceptualize race conditions, off-by-one errors, and state-desyncs. It does not care what the code is *supposed* to do, only how it can technically fail.

**5. Synthesis Director (The Arbiter)**
*   **Role:** Executive summary and remediation formatting.
*   **Function:** Ingests the findings from the previous 4 agents. Its job is to filter out semantic noise and false positives, consolidating the genuine vulnerabilities into a strictly formatted, actionable Markdown ledger.

**Date/Time Entered:** 2026-06-23T12:15:00-04:00

Introduce an interactive modal that pops up when clicking an individual node within the Flow Line. This modal will allow granular, per-node configuration overrides. Initially, this would house radio buttons for "Payload Options" letting operators toggle between passing the full "Unified Ledger" or just a "Node Ledger" (the direct output of the preceding node). **Status:** Unfulfilled

### Linear Flow & Special Nodes Enhancements
- **Branching & Aggregation Nodes**: DET_FAN_OUT to dynamically spawn N parallel sub-tasks/branches. DET_SYNTHESIZE (or DET_AGGREGATE) to wait for multiple prerequisite branches to finish and merge their payloads.
- **Filtering & Parsing Nodes**: DET_FILTER_IN to conditionally pass payload forward based on regex/keyword matching. DET_EXTRACT to isolate specific text using regex capture groups.
- **Dynamic Routing**: DET_DYNAMIC_ROUTER to route based on payload contents rather than static loop counters.
- **Webhooks**: DET_WEBHOOK for lightweight HTTP event triggers.
- **Local Edge LLM Sync Node (S25 Ultra Integration)**: A node that drops a payload into a specific Google Drive folder, paired with a watchdog node that polls the folder for a response from an edge local LLM (polling every few minutes, scaling to every 5 seconds when active, then scaling back down after 5 minutes of inactivity). Useful for S25 Ultra or status updates on edge nodes.

### Feature Name: Multi-Tier Grounding Options & Hybrid Exclusionary Search
**Abstract:** Add "Grounding with Local Memory" and "Grounding with Brave LLM Search" toggles to the Agent Builder, with complex exclusionary logic when multiple groundings are active.
**Date/Time Entered:** 2026-06-24T17:30:00-04:00
**Status:** Unfulfilled

**Description:**
Add "Grounding with Local Memory" and "Grounding with Brave LLM Search" toggles to the Agent Builder right below Grounding with Google Search. 
- **Hybrid Exclusionary Search**: If Google and Brave are both turned on at the same time, it automatically triggers logic to wait for the model to do its Google searches, the agent thinks about the Google search results and selects sources, and then uses what it's learned to do a Brave search that explicitly ignores results already discovered by the Google search, before continuing. If both are turned on, the agent *always* uses this hybrid exclusionary search logic. 
- **Tri-Grounding Logic**: If all 3 Groundings (Google, Brave, Local Memory) are turned on, the agent's system prompt must be dynamically injected with context explaining *why* it would search its project memory and that it has the capability to do so. It must be explicitly instructed that project memory is only a source of truth if referencing the project and project-related contexts (to avoid hallucinating local data as global internet facts).
