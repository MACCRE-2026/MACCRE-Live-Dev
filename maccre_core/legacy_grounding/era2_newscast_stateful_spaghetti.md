# Era 2: NewsCast (Stateful Spaghetti)

## Chronological & Conceptual Evolution
Following the limitations of DiamondLoop, `NewsCast` attempted to modularize the system. It introduced JSON-based `AgentTemplates`, a `Director` to synthesize dynamic `ShowScript` DAGs, and a `TopologyManager` for routing logic. However, the architecture mutated into a monolithic FastAPI web server (`app_api.py`) where business logic, state, and HTTP transmission became hopelessly entangled.

## Core Breakthroughs
- **Decoupled Agent Manifests**: Moving personas into external `.json` configuration files, proving the viability of abstract agent definitions.
- **Server-Sent Events (SSE) Streaming**: Implementing realtime, token-by-token or phase-by-phase JSON emission via asynchronous generators, allowing the frontend to react to the swarm dynamically.
- **Phase-Based Execution**: The realization that swarms need "Goals" (Phases) generated by a high-level Director node before execution begins.

## Dead Ends & Spaghetti
- **Stateful Swarm Instances**: The `SwarmEngine` class held the entire conversation `history` internally. This meant the swarm could not be paused, serialized, or distributed across edge nodes without massive state-sync nightmares.
- **Buried Side-Effects**: FFmpeg manifest generation (`stitcher.py`) and audio/TTS commands were buried directly inside API route handlers.
- **Spaghetti Warning**: **ALL orchestration must be completely stateless.** The `maccre_router.py` must take `history` as an explicit input argument and return the delta. Additionally, pure functions (like FFmpeg string building) must be strictly isolated from side-effect execution (`os.system`).
