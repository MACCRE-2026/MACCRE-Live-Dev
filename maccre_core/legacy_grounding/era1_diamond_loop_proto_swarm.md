# Era 1: Diamond Loop (Proto-Swarm)

## Chronological & Conceptual Evolution
The `DiamondLoop-LEGACY` architecture represents the genesis of MACCRE's multi-agent experimentation. The engine was designed as a static, rigid Map-Reduce loop where ideas were generated by "Physicists" and critiqued by an "Audience." The mathematical drift here was purely sequential: prompt -> map (gather N responses) -> reduce (compile into single context) -> map (gather N critiques) -> reduce.

## Core Breakthroughs
- **Asynchronous Horizontal Scaling**: The successful implementation of `asyncio.gather` natively over the `google-genai` SDK endpoints proved that the IDE could handle massive concurrent agent invocations without blocking the event loop.
- **Context Compaction**: Generating [LogID] tags and compiling raw outputs into unified context blocks established the foundation for tracking provenance in multi-agent swarms.

## Dead Ends & Spaghetti
- **Tight Coupling of Personas**: System prompts for the Physicists and Audience were hardcoded directly into `backend.py`. There was no separation of concerns between "what the agent is" and "how the loop routes data."
- **Rigid Topologies**: The 5-loop cycle was mathematically hardcoded into `range(1, total_loops + 1)`. 
- **Spaghetti Warning**: **NEVER hardcode agent personas or generation logic directly into the orchestration loop.** Operations must ingest parameterized `AgentRecord` schemas, ensuring the orchestrator remains ignorant of the domain content.
